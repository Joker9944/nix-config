# Update Log

## 2026-07-29

* **Creation**: Added the **profiles** layer — a role tier above the mixins (prep for onboarding servers, whose role diverges sharply from the desktops). A profile is a plain module under `hosts/profiles/*.nix` that bundles a *class* of machine's mixin `enable`s; `mkNixosConfiguration` gained an optional `profile` string arg, resolved to `hosts/profiles/<profile>.nix` next to the host module (same `context`/site as `hostname`), and each `flake.nix` host record now carries `profile = "hyprland-desktop"` — so the flake registry shows machine→role at a glance. Both hosts' `mixins.nix` shrank to per-host **deltas** (HAL9000: `nvidia`/`steam`/`ffmpeg`/`docker`/`windowsSupport`; wintermute: `openssh`/`windowsSupport`); the shared graphical baseline moved into `base` ← `desktop` ← `hyprland-desktop` (linear `imports` chain, IS-A). This realized the `TODO move to a desktop blueprint` marker: `console.useXkbConfig` now lives in `desktop` (per-host `xkb.layout` stays in the host). **Design calls** (new decision [host-profiles](/decisions/host-profiles.md)): one profile per host — a *string*, not a list; orthogonal multi-role machines (a k8s node that is also a NAS) are modelled as **mixins**, not a profile list, keeping composition flat and in one place; `base` is reached through the `imports` chain, **not** injected by the builder. **Enshrined guard**: profiles are high-level and *shared* — a profile that would serve exactly one host is forbidden (that's a host delta), the guard against per-machine profile proliferation. New concept [architecture/profiles](/architecture/profiles.md); updated [mixin-pattern](/architecture/mixin-pattern.md) (the three-tier mixin/profile/host split + NixOS enables now come mostly from the profile), [entry-points](/architecture/entry-points.md) (fourth module source + `custom.config.profile`), both host docs, and the two indexes. Verified both `nixosConfigurations` evaluate to the byte-identical enable set they had pre-refactor.
* **Refactor**: Mixin-purity pass — brought every mixin back to strict binary `enable`, removing the per-host and parametric options that had crept in (prep for onboarding servers, which need lean, graphical-free hosts). Per mixin:
  * `keymap` **dissolved**: the `type` enum was per-host data; inlined to each host as `services.xserver.xkb.{layout,variant}` + `console.useXkbConfig` (`hosts/HAL9000`, `hosts/wintermute`), mixin deleted. `console.useXkbConfig` carries a `TODO move to a desktop blueprint` marker — it's a desktop-only concern (tty↔xkb match) irrelevant to SSH-only servers.
  * `hardware/disko` **dissolved to lib**: the layout template + `main.name`/`size.*`/`layoutVersion` options became `custom.lib.disko.mkDiskoLayout { config, template ? templates.version1 }` with `templates.version{1,2}`; each host's `disks.nix` now imports `inputs.disko.nixosModules.disko` itself and calls the helper (HAL9000 keeps its extra `games` disk via `lib.mkMerge`). This is the "third case → promote to a helper" the [enable-flag-mixins](/decisions/enable-flag-mixins.md) trade-off predicted — a parametrized template is a function, not an `enable` flag.
  * `services/maintenance` + `pwas/{youtube,jellyfin,audiobookshelf}` **normalized to `mkMixinModule` sugar**: fixed data (the `flake` URL; PWA name/urlBase/profile+site ULIDs) inlined, dropping the manual options/`_:` shape. PWA ULIDs hoisted to a `let` with `# cSpell:disable-line` (cspell is editor-only, not a gate).
  * `steam` (hm) **normalized to sugar**: the `enable.default = osConfig…` follow moved to `users/joker9944/default.nix`, alongside the existing `desktopEnvironment` re-export — the one documented place the two trees share state. gamemode-follows-system-steam behavior preserved (verified on both hosts).
  * `boot` **decomposed into a category**: the single 3-loader mixin split into `boot/loader/{limine,systemdBoot}` leaves (grub dropped as unused; systemd-boot kept for future servers), `secureBoot` inlined as `limine.secureBoot.enable = lib.mkDefault true`, `efi.canTouchEfiVariables`/sbctl folded into `limine`, and `mixins.boot.enable` dropped (its base config was gone). New **mutually-exclusive category** guard: `boot/loader/default.nix` asserts `lib.count … (lib.attrValues config.mixins.boot.loader) <= 1`, deriving the loader set from the namespace so a future loader auto-registers rather than silently escaping a hardcoded list. Hosts select via `mixins.boot.loader.limine.enable = true`.

## 2026-07-23

* **Tooling refactor**: The options-lookup engine is now a Nix factory (`mkOptionsTool`) that bakes a dataset's `options.json` into a small `writeShellApplication` binary — one per dataset (`hm-options`, `nixos-options`). This drops the old per-call `nix build` (and the `hm-doc` path-cache from `86859d8`): every query is just `jq` (~46 ms), and the binaries land on `PATH` via a new `devShells.default` + `.envrc` (`use flake`, `nix-direnv`-cached). Removed the `home-manager-docs-json` / `nixos-docs-json` **package outputs** — they existed only to be `nix build`-able; the JSON is now vendored into the tools. The NixOS JSON is a bare `eval-config` (`modules = [ ]`) → vanilla in-tree options only (cache-hits the Hydra `options` artifact; excludes this repo's mixins/external modules unless `documentation.nixos.includeAllModules = true`). The factory, JSON resolution, and engine (`files/nix-options.sh`) live under `pkgs/nix-options/`, whose `default.nix` returns `{ hm-options; nixos-options; }` directly. `flake.nix` stays lean — it only wires the dev shell to `self.packages.<system>.{hm,nixos}-options`. `pkgs/default.nix` now discovers in two passes: top-level `.nix` files → `callPackage` (get `flake`), and top-level subdirectories → `import path args` (get full args incl. `inputs`), each returning an attrset of packages merged into the set. So a file is one package and a subdir is a flake-aware package-group; `inputs` is threaded via `args` rather than `callPackage`. Captured as new concept [packages](/architecture/packages.md). Deleted `.claude/skills/home-manager-options/scripts/hm-doc`; the `home-manager-options` skill now calls the on-`PATH` `hm-options`. Updated [lookup-hm-option](/workflows/lookup-hm-option.md) and the `CLAUDE.md` companion-tooling bullet. **Next step**: a dedicated `nixos-options` skill (SKILL.md + NixOS trap table + evals) consuming the already-built `nixos-options` binary. `nix-darwin` would slot in as one more `mkOptionsTool` call when it becomes a flake input.
