# DP-2 colour and HDR

DP-2 is a Dell AW2724DM, the only HDR-capable panel across both hosts. Its EDID advertises ST.2084 (PQ), BT.2020 RGB/YCC, native 10 bpc, max luminance 630 cd/m², min 0.031 cd/m² with local dimming (0.082 without), and primaries near DCI-P3. HDR is **on demand rather than always on**: the desktop stays SDR and only a fullscreen app presenting a PQ surface flips the panel, which avoids tuning SDR-in-PQ mapping and local-dimming bloom on desktop UI.

Most of that needs no configuration, and the absences are deliberate:

* `CMonitor::supportsHDR()` derives from the EDID (`supportsBT2020` && `hdrMetadata->supportsPQ`), so it is already true for DP-2 with nothing set.
* `render:cm_auto_hdr` defaults to `1` and `render:cm_enabled` to `true` — the fullscreen auto-switch is upstream default behaviour, not restated in nix.
* `min_luminance` / `max_luminance` / `max_avg_luminance` default to `-1`, which reads the EDID figures above. Pinning them in nix would copy panel data into a file that cannot follow a monitor swap.

The DP-2 monitor rule sets `bitdepth = 10` and `cm = "edid"`. Hyprland does **not** raise bit depth on its own when wide-gamut or HDR engages — it warns and raises an on-screen notification instead (there is a standing `FIXME` beside that check in `Renderer.cpp`), and HDR at 8 bit bands. It also tips `render:use_fp16`'s `auto` into using the fp16 internal buffer.

Since hyprland is pinned to an upstream tag bumped independently of the nixos release train (see [release-policy](/decisions/release-policy.md)), that "correct by default" set is a live dependency: if HDR stops auto-engaging after a bump, check whether `cm_auto_hdr`'s default moved before suspecting the monitor rule.

`cm = "edid"` maps SDR content onto the panel's EDID primaries; at the default `srgb` the wider native gamut oversaturates the desktop. `SUPER + D` flips DP-2 between that and `hdredid` (always-on HDR) at runtime; a config reload restores `edid`. The rule is let-bound as `hdrMonitor` because `hl.monitor` replaces the whole rule, so the bind must resend every field.

Games reach HDR through Proton's wayland driver, not gamescope. `PROTON_ENABLE_WAYLAND=1` and `PROTON_FORCE_HDR=1` are set globally on the Steam package (`modules/nixos/hosts/HAL9000/steam.nix`); `=0` in a title's launch options opts out. `FORCE`, not `ENABLE`: winewayland takes a monitor's HDR capability from the compositor, which reports DP-2 as SDR until `cm_auto_hdr` engages, so without the force games never offer HDR. HDR forced on an XWayland title renders washed out, so the two only make sense together. Valve's builds ship no `winewayland.drv` and ignore both; the compatibility tool must be forced to GE-Proton per title, since Steam's global default tool loses to Valve's per-title mapping. `~/.local/share/Steam/logs/compat_log.txt` says which build actually won.

`quirks:prefer_hdr` is deliberately unset — DXVK negotiates against the color-management protocol's *supported* transfer functions, not the *preferred* image description that `prefer_hdr` overrides (gamescope is the client that reads the latter). It would also hurt here: real EDID luminances reach clients only when `monitors().size() == 1`, so with three monitors it would advertise `DEFAULT_HDR_IMAGE_DESCRIPTION`'s 10000 cd/m² to a 630-nit panel.

Live experiments on any of this go through `hyprctl eval`, not `hyprctl keyword`; see [hyprland-lua-config](/architecture/hyprland-lua-config.md).

# Host record & mixin selection

Host record: `flake.nix#nixosConfigurations`, selecting `profile = "hyprland-desktop"` — the source of the graphical baseline (see [profiles](/architecture/profiles.md)). `modules/nixos/hosts/HAL9000/mixins.nix` holds only the deltas on top: `amdCpu`, `nvidia`, `nvidiaCuda`, `steam` (with its `resolution`), `ffmpeg`, `docker`, `windowsSupport`. Per-host quirks (red limine boot branding, `system.stateVersion = "24.05"`, regreet window rule pinned to DP-2, the desktop-only `hardware.nvidia` overrides): `modules/nixos/hosts/HAL9000/default.nix`.

Home-manager side: `modules/home/users/joker9944/hosts/HAL9000/default.nix`. Host-specific additions worth calling out:

* Gaming stack: Prism Launcher, Lutris, Steam autostart entry.
* Multiple Librewolf profiles: Work / Homework.
* `programs.yas.config.gpu = true;` — HAL9000-only because the GPU widget depends on the discrete GPU.
* GNOME touchpad disabled — guarded by `mixins.desktopEnvironment.gnome.enable`, so it's inert under hyprland.
