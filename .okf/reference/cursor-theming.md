# The format has no hook

XCursor is pre-baked ARGB pixmaps. There is no stylesheet to rewrite the way
[/reference/gtk-theming.md](/reference/gtk-theming.md) describes for an icon pack, and no
foreground colour the toolkit supplies. The only way in is upstream of the format, at the SVGs
Breeze is drawn in — so `schemes.cursors` compiles a theme rather than recolouring one, and
`vendor/cursors/breeze` is the source it compiles from.

# Slots

All 91 Breeze SVGs together use nine roles. There are no `style=` attributes, no `stroke` and
no classes.

| slot | Breeze literal | default |
|---|---|---|
| `fill` | implicit black, `#0d0d0d` | `base06`, swapped with `outline` on a light scheme |
| `outline` | `#fff` | `base00` |
| `shadow` | implicit black under a `filter`, `#0a0a0a`/`#070707`/`#0c0c0c` | black |
| `accent` | `#46a7ac` | `scheme.accent` |
| `accentAlt` | `#d4497f` | `base0C` |
| `negative` | `#ed1515` | `base08` |
| `positive` | `#11d116`, `#18c087` | `base0B` |
| `info` | `#3daee9` | `base0D` |
| `neutral` | `#f67400` | `base09` |

# Most of the paint is not written down

196 of 344 elements carry no `fill` and take the SVG default of black — cursor body, drop
shadow and `crosshair.svg`'s gradient stops alike, which is why matching hex literals misses
the majority of the artwork. Two signals separate them, and in all 91 files they are exact:

* `filter="url(#…)"` marks a shadow. It appears only on blurred copies, always paired with
  `opacity`.
* The effective paint is resolved **down the tree**, not read per element — `help.svg` draws a
  `<circle>` that inherits `fill` from a `<g>` ancestor.

`id="hotspot"` is skipped: `display="none"`, never rasterised.

An unmapped paint fails `nix run .#update-cursor-templates`, naming file and element. That is
how a new upstream role surfaces.

# Only the Breeze variant is templated

Breeze_Light is not a recolour of it. Its outline is `opacity=".6"` over implicit black rather
than a colour, it carries two unblurred 20% scrims (`no-drop`, `not-allowed`) with no
counterpart, and its badge geometry differs. Supporting both would make `outline` mean an
opaque colour in one set and 60% of a colour composited over the backdrop in the other.

It would buy nothing: swapping `fill` with `outline` already yields the dark-on-light cursor,
because the badge's white ring becomes the light `outline` and supplies the separation
Light's extra ring exists to provide.

# What comes out

One theme directory under `share/icons/<name>`, because all three consumers find a theme the
same way — by name on `XDG_DATA_DIRS`:

* `cursors/` — XCursor, for XWayland, GTK and anything reading `XCURSOR_THEME`
* `cursors_scalable/` — KDE's SVG cursor format, read by KWin
* `hyprcursors/` + `manifest.hl` — hyprcursor, which renders SVG at the size asked for

Hotspots, frame delays and nominal sizes come from the vendored upstream metadata rather than
the `#hotspot` rect, which would need ancestor transforms composed — `crosshair.svg`'s carries
`transform="rotate(90)"`. That is the whole reason upstream's own generator needs Qt; `resvg`
and `xcursorgen` are the only tools here, and a full theme builds in under three seconds.

## Sizes disagree between the two stacks

Breeze draws a nominal 24 on a 32-unit canvas, and 90 of its 91 shapes use the whole of it.
XCursor carries the nominal size as metadata, so a nominal 24 is a 32px pixmap. hyprcursor
renders an SVG into a `size × size` box (`libhyprcursor/hyprcursor.cpp:567`), so the same
request gives artwork at ¾ scale. Cropping the canvas would clip, so the request is scaled
instead: `HYPRCURSOR_SIZE = XCURSOR_SIZE * 32 / 24`.

The size ladder is spelled in nominal sizes rather than upstream's percentages, so that 16 —
which Breeze omits — exists.

# Two checks, and what each one catches

Neither is about how the theme looks; `nix run .#preview-cursors` tiles a built theme into one
PNG for that.

* **`cursorIdentity`** — a template keeps upstream's literal beside the `data-slot` it records,
  so it renders standalone and is byte-comparable to its source. Catches a mis-slotted paint, a
  hand-edit, and a `breeze` input bumped without re-running the app. That last one is why the
  input is pinned to a tag: the templates are regenerated by hand, unlike
  [/decisions/vendored-schemes.md](/decisions/vendored-schemes.md), whose tree is refreshed on a
  schedule because upstream moves weekly. Breeze's SVGs have taken three commits since July 2024.
* **`cursorSlotLeak`** — builds with all nine slots mapped to pure reds where `green == blue`, a
  property every blend between them preserves, and asserts it of every solid pixel. Breeze's own
  palette is teal, pink, orange, green, blue, white and black, so a paint that escaped the
  classifier cannot hide.
